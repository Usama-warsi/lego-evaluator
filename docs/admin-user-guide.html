LEGO Evaluator
Admin User Guide

Complete guide to setting up, configuring, and managing the Toy Exchange LEGO Evaluator plugin for WooCommerce.

Installation

1
Upload the plugin Go to WordPress Admin → Plugins → Add New → Upload Plugin. Upload the lego-evaluator.zip file and click Install Now.
2
Activate Click Activate Plugin. You will now see a LEGO Evaluator menu item in your WordPress admin sidebar.
3
Confirm WooCommerce is active The plugin requires WooCommerce 5.0+. If WooCommerce is not active the cart functions will not work.
4
Configure API credentials Navigate to LEGO Evaluator → API Credentials and enter your Bricklink API keys (see next section).
ℹ️
PHP 7.4+ and WordPress 5.8+ are required. The plugin is tested up to WooCommerce 8.x.

BrickLink API Setup

The evaluator fetches live market prices and set details from the BrickLink API. You need a free BrickLink seller account to get API credentials.

1
Log in to BrickLink Go to bricklink.com and log in with your store account.
2
Open the API consumer page Navigate to My BL → Settings → API Consumer Registration.
3
Register a new consumer Add your domain as the registered IP/domain. Save the Consumer Key and Consumer Secret.
4
Generate a token On the same page, create a token and save the Token Value and Token Secret.
5
Enter credentials in the plugin Go to LEGO Evaluator → BrickLink API and paste all four values, then click Save Changes.
FieldWhere to find itExample length
Consumer KeyAPI Consumer Registration page~32 characters
Consumer SecretAPI Consumer Registration page~32 characters
Token ValueToken generation section~32 characters
Token SecretToken generation section~32 characters
⚠️
If you see "BrickLink API credentials missing" errors in the Logs tab, double-check that all four fields are saved correctly. Trailing spaces will cause authentication failures.

Rebrickable API Setup

Rebrickable powers the set name search on the frontend. BrickLink does not provide a search-by-name endpoint, so customers can type a set name (e.g. "Millennium Falcon") and see a grid of matching sets before selecting one for evaluation.

1
Create a free Rebrickable account Go to rebrickable.com and register a free account.
2
Get your API key Log in, open your profile menu → Settings → API. Your API key is listed there. Click Generate Key if none exists.
3
Enter the key in the plugin Go to LEGO Evaluator → BrickLink API, scroll to the Rebrickable API section, paste your key, and click Save Changes.
ℹ️
Without a Rebrickable API key, name search is disabled. Customers can still type a set number directly into the search box and click Search to evaluate it via BrickLink.

WooCommerce Product Setup

The evaluator adds sets to the cart as a single WooCommerce product. The price of that product is overridden with the calculated offer each time it is added. You need to create this product first.

1
Create a Simple Product Go to WooCommerce → Products → Add New. Name it something like "LEGO Set Evaluation". Set the price to 0 — the plugin will override it at checkout.
2
Publish the product You can hide it from the shop by setting its Catalog visibility to Hidden in the product's Publish panel.
3
Link it in the plugin settings Go to LEGO Evaluator → General Settings and select this product from the Evaluated Product dropdown.
ℹ️
Variable products are supported — the plugin automatically picks the first available variation. However, a Simple Product is recommended for simplicity.

Pricing Tier Rules

Pricing Tiers let you pay a different percentage of market value depending on how expensive the set is. Higher-value sets can have higher or lower payout percentages based on your business model.

ℹ️
Important: The Pricing Tier percentages are the starting base percentages for condition deductions. The Condition Rules tab then applies further deductions on top of these. In the current version, the tier lookup is done but the actual payout percentages come from the Condition Rules tab — the tier percentages serve as a reference framework.

How to configure tiers

Go to LEGO Evaluator → Pricing Rules.

Acceptance Toggles

Acceptance Toggles let you temporarily stop accepting specific types of sets without changing your pricing rules. When a type is disabled:

  • The option is hidden from customers on the frontend evaluator
  • The backend rejects any calculation attempt for that type (safety net)
  • All other set types continue working normally
  • No pricing rules are deleted — re-enabling the toggle instantly restores full functionality

The five toggles

Accept New — Seals Intact
Enabled
Accept New — Seals Broken (Open Box)
Enabled
Accept Used — 100% Complete
Enabled
Accept Used — Over 95% Complete
Disabled
Accept Used — Under 95% / Mixed
Disabled

In the example above: customers can only submit New sets or Used 100% Complete sets. The "Over 95%" and "Under 95%" options are hidden.

How to change a toggle

1
Go to Condition Rules tab Navigate to LEGO Evaluator → Condition Rules and scroll to the bottom — the Acceptance Toggles section is at the end.
2
Check or uncheck the box Tick = accepting that type. Untick = temporarily not accepting.
3
Save Changes Click the blue Save Changes button. Changes take effect immediately for all new visitors — no cache flush needed.
✅
If you disable all options under New, the "New" condition card disappears entirely from the frontend. Same for Used. Customers only see the choices you are currently accepting.

Used Price Fallback

BrickLink sometimes has no sold or stock data for a used set — especially newer releases or less popular sets. Without this fallback, the used price would default to £0, which would cause incorrect or zero offers even for valuable sets.

How it works

When the plugin detects that the BrickLink used average price is £0, it automatically estimates the used price as a percentage of the new price:

estimated_used_price = new_avg_price × (fallback_percentage / 100)
Example — Set 75418 (no BrickLink used data)
BrickLink new average: £30.00
BrickLink used average: £0.00 (no data)
Fallback % setting: 70%

→ Estimated used price = £30.00 × 70% = £21.00
→ Customer submits Used 100% Complete (Built) at 55% → offer = £21.00 × 55% = £11.50

A visible amber notice is shown to the customer on the frontend when the fallback is active: "No used sold data found on BrickLink — used price is estimated at 70% of new price."

Changing the fallback percentage

Go to LEGO Evaluator → Condition Rules → Used Price Fallback. The default is 70% (30% off new). Adjust to match your typical new-to-used price ratio for LEGO in the UK market.

Fallback %MeaningWhen to use
70%30% off new priceDefault — reasonable for most LEGO sets
60%40% off new priceIf your market shows larger new-to-used gap
80%20% off new priceFor premium/rare sets where used stays close to new

General Settings

Evaluated Product

This dropdown lists all WooCommerce products. Select the shell product you created during setup. Every time a customer adds a LEGO evaluation to their basket, this product is added with a dynamically overridden price equal to the offer.

⚠️
If you change this product later, any existing cart sessions will reference the old product ID. Clear WooCommerce session data or ask customers to clear their cart if issues arise.

Debug Mode

When enabled, every Bricklink API call is logged to tee-api-debug.json in the plugin directory. The last 20 calls are kept. View them in the Logs tab.

  • Enable when troubleshooting missing prices or API errors
  • Disable on production to reduce file I/O
  • Do not leave enabled permanently — the log file will grow and could expose API request details

Logs Tab

The Logs tab shows a reverse-chronological list of the last 20 Bricklink API requests. Each entry shows:

  • Timestamp
  • HTTP method and endpoint (e.g. GET items/SET/75192-1/price)
  • Parameters sent (expandable)
  • Full API response (expandable)

Deleting logs

Click the Delete Logs button at the top of the tab to immediately delete the log file. A confirmation prompt is shown first.

ℹ️
Debug Mode must be enabled (General Settings tab) for logs to be collected. If the log file doesn't exist yet, the tab will say "Log file not found."

Adding the Evaluator to a Page

The evaluator is added to any page or post using a shortcode:

[lego_evaluator]
1
Create or edit a page Go to Pages → Add New (or edit an existing page like /sell-your-lego/).
2
Add a Shortcode block In the Gutenberg editor, add a Shortcode block and paste [lego_evaluator].
3
Publish and test Visit the page as a customer and try searching for a set number such as 75192.

Customer Journey

This is what a customer experiences on the evaluator page.

1
Search by name or set number The customer types a set name (e.g. "Millennium Falcon") or a known set number (e.g. 75192). When text is entered, the plugin queries Rebrickable and displays a grid of matching sets with images, years, and part counts. The customer clicks the correct set from the grid.

If a pure number is typed and the Search button is pressed, the plugin goes directly to BrickLink — skipping the grid for speed.
2
BrickLink data loads After the customer selects a set from the grid (or enters a number directly), the plugin fetches set details, new/used prices, and minifigure data from BrickLink in real time.
3
Select condition Both New and Used cards are shown. Disabled options display an amber notice if selected. The customer selects the appropriate condition.
3
Answer condition questions Dynamic questions appear based on condition:
  • New: Are seals intact? → Box condition or completeness
  • Used: How complete? → Built/unbuilt, box/instructions
4
Verify minifigures If the set contains minifigures, they are listed with quantity selectors. The customer marks any that are missing.
5
See the offer A result banner shows the calculated offer price updated in real time. The customer can accept or continue evaluating more sets.
6
Add all to basket Accepted evaluations appear in a list. When ready, the customer clicks Add All to Basket and is redirected to the WooCommerce cart.

Cart & Checkout Behaviour

Each accepted evaluation appears as a line item in the WooCommerce cart. The plugin automatically handles several things:

What the plugin doesHow it works
Override priceThe shell product's £0 price is replaced with the calculated offer for each line item.
Show LEGO set imageThe set's BrickLink image replaces the product thumbnail in cart and admin order view.
Display evaluation detailsSet name, condition, completeness, weight, etc. appear as line item meta in cart and checkout.
Set correct weightThe set's BrickLink weight (in grams, converted to your WooCommerce unit) is applied to the product so shipping rate plugins calculate correctly.
Save to orderAll evaluation details and the set image URL are stored as order item meta, visible in WooCommerce order admin.
ℹ️
Weight is stored as _tee_weight_grams in order item meta and automatically converted to your store's weight unit (kg, lbs, oz, g) when shipping plugins read it.

Example: Full Pricing Calculation

Let's walk through a real example: Set 75192 Millennium Falcon, submitted as Used, 100% Complete, Unbuilt, with Box but no Instructions. One minifigure is missing (Han Solo, market value £8.00).

BrickLink Data
New Average: £480.00 | Used Average: £320.00
Base: Used 100% Unbuilt (45% of £320.00)£144.00
Box only deduction (5% of £144.00)− £7.20
Subtotal after box deduction£136.80
Missing minifig deduction (£8.00 × 2.0 multiplier)− £16.00
Raw offer£120.80
Rounded to nearest £0.50£121.00
✅
The customer sees £121.00 as the offer. They click "Accept Evaluation" and it is added to the basket at that price.

Example: Toggle Scenarios

Practical examples of when and how to use Acceptance Toggles.

Scenario A — Christmas Rush: Stop accepting incomplete sets

During peak periods you only want complete sets. Uncheck:

  • Accept New — Seals Broken
  • Accept Used — Over 95% Complete
  • Accept Used — Under 95% / Mixed

Customers will only see New Sealed and Used 100% Complete options. All others are hidden.

Scenario B — Warehouse Full: Stop accepting used sets entirely

Uncheck all three used toggles:

  • Accept Used — 100% Complete
  • Accept Used — Over 95% Complete
  • Accept Used — Under 95% / Mixed

The entire "Used" condition card disappears from the frontend. Customers can only submit new sets.

Scenario C — New only

You want to test accepting only New Sealed sets this week. Uncheck everything except:

  • Accept New — Seals Intact

The "Used" card disappears. On the "New" flow, the "Are seals intact?" question is skipped and the customer goes straight to the box condition question (since only one seal option remains, it is auto-selected).

Example: Baseplates & Road Plates

Sets whose names contain the words Baseplate or Road Plate are automatically priced by weight for used condition rather than by market average. This is because BrickLink market prices for these items don't reflect their practical resale value as loose LEGO.

Example — Set 11008 "Bricks and Houses" (Baseplate)
BrickLink used average: £12.00 (would normally be used as base)
Set name matches "Baseplate" keyword → weight-only pricing applied

Customer enters weight: 400g
Used Mixed Rate: £4.25/KG

→ 0.4 KG × £4.25 = £1.70 → rounded to £1.50
ℹ️
This rule only applies to used condition. New Baseplate sets still use normal market-price based calculations.

The matching is case-insensitive and matches partial words. Both "Green Baseplate" and "Road Plates Pack" would be caught.

Example: No BrickLink Used Data

Some sets — particularly recent releases or niche sets — have no recorded used sales on BrickLink. Without a fallback, the used average would be £0 and customers would see a zero offer.

Example — Set 75418 (no used BrickLink data at time of evaluation)
BrickLink new average: £28.99
BrickLink used average: £0.00 (no sold listings recorded)
Fallback % configured: 70%

System estimates used = £28.99 × 70% = £20.29

Customer submits Used 100% Built (55% of estimated £20.29):
→ £20.29 × 55% = £11.16 → rounded to £11.00

The customer sees an amber notice on screen: "No used sold data found on BrickLink — used price is estimated at 70% of new price." This keeps them informed without blocking the transaction.

⚠️
If BOTH new and used prices are £0 (set not found on BrickLink), the offer will return £0 and the customer is redirected to the rejection URL. This usually means the set number was entered incorrectly.
