LEGO Evaluator
Developer Reference

Architecture overview, class reference, AJAX protocol, WooCommerce hooks, options reference, and extension patterns for the Toy Exchange LEGO Evaluator plugin.

Version 1.1.0 Requires WP 5.8+ Requires PHP 7.4+ Requires WC 5.0+

Plugin Overview

The Toy Exchange LEGO Evaluator is a WordPress plugin that integrates the BrickLink Marketplace API with WooCommerce to provide a frontend tool for customers to get instant cash-buy offers for LEGO sets they want to sell.

Three-layer architecture

Data Layer

TEE_Bricklink_API handles all OAuth1 signed requests to api.bricklink.com. Returns set metadata, price guides (new/used), and minifigure subsets.

Logic Layer

TEE_Evaluator_Logic applies the admin-configured pricing rules, condition rules, acceptance toggles, and special filters (Baseplates etc.) to produce a final offer in GBP.

Presentation Layer

frontend-ui.js drives the entire UI state machine — search, dynamic question rendering, minifig management, offer display, and batch cart submission.

WooCommerce Layer

lego-evaluator.php global hooks override cart item prices, weights, thumbnails, and persist evaluation metadata to orders.

Class: TEE_Bricklink_API PHP

Defined in includes/bricklink-api.php. Handles all communication with the BrickLink REST API using OAuth 1.0a HMAC-SHA1 signing.

public function get_item_data($set_number): array|WP_Error
Fetches set metadata from items/SET/{set_number}. Appends -1 suffix if not already present. Returns associative array with no, name, weight, image_url keys.
public function get_price_guide($set_number, $new_or_used = 'N', $item_type = 'SET'): array|WP_Error
Fetches the price guide with a 3-tier fallback strategy:
1. GB sold listings (currency GBP)
2. Global sold listings (all currencies)
3. Global stock listings (items currently for sale)
Returns array with avg_price, qty_avg_price, min_price, max_price.
public function get_subsets($set_number): array|WP_Error
Fetches the breakdown of items in a set from items/SET/{set_number}/subsets with breakdown=true. Returns array of subset groups, each with an entries array. Only entries where item.type === 'MINIFIG' are used by the evaluator.

OAuth1 Signing (private request())

// Signature base string construction
$base_string = strtoupper($method) . '&'
             . rawurlencode($base_url . $endpoint) . '&'
             . rawurlencode(http_build_query($all_params, '', '&', PHP_QUERY_RFC3986));

// Signing key
$signing_key = rawurlencode($consumer_secret) . '&' . rawurlencode($token_secret);

// HMAC-SHA1 signature
$signature = base64_encode(hash_hmac('sha1', $base_string, $signing_key, true));
⚠️
All OAuth params (oauth_timestamp, oauth_nonce) must be merged with query params before sorting for the base string. Sorting is done with ksort(). The query params must NOT be URL-encoded twice — use PHP_QUERY_RFC3986 in http_build_query.

Debug logging

When tee_debug_mode option is truthy, each API response is appended to TEE_PLUGIN_DIR . 'tee-api-debug.json'. The array is capped at 20 entries (oldest removed first). Each entry contains:

{
    "timestamp": "2025-05-08 14:23:01",
    "endpoint":  "items/SET/75192-1/price",
    "method":    "GET",
    "params":    { "new_or_used": "U", "guide_type": "sold", ... },
    "response":  { "meta": {...}, "data": {...} }
}

Class: TEE_Rebrickable_API PHP

Defined in includes/rebrickable-api.php. Provides set name/keyword search via the Rebrickable v3 REST API. BrickLink has no search endpoint, so this class fills that gap.

public function search_sets($query, $page_size = 10): array|WP_Error
Calls https://rebrickable.com/api/v3/lego/sets/?search={query}&page_size={n}&ordering=-year.
Returns an array of normalised set objects on success, an empty array if no results, or a WP_Error if the key is missing or the request fails.

Each returned item has the shape: 
{
    "set_num":  "75192",      // trailing -1 suffix stripped
    "name":     "Millennium Falcon",
    "year":     2017,
    "parts":    7541,
    "image":    "https://cdn.rebrickable.com/..."
}

Authentication

Uses a simple API-key header: Authorization: key {tee_rebrickable_api_key}. The key is stored in the WordPress options table as tee_rebrickable_api_key and entered via LEGO Evaluator → BrickLink API → Rebrickable API Key.

Class: TEE_Evaluator_Logic PHP

Defined in includes/evaluator-logic.php. Contains the full pricing decision tree. Stateless — instantiated per AJAX request.

public function calculate_offer($set_data, $user_inputs): float|array
Returns a float (the offer in GBP, rounded to nearest £0.50) on success. Returns an associative array ['rejected' => true, 'rejection_url' => '...'] on rejection.

Decision tree

// Simplified decision tree

if (set_name contains "baseplate" OR "road plate" AND condition == "used")
    → weight-only pricing at used_mixed_rate £/KG
    → return early

if condition == "new":
    if !accept_new_sealed AND seals_intact → reject
    if !accept_new_open  AND !seals_intact → reject

    if seals_intact:
        offer = new_avg × new_sealed_[box_cond]%
    else if is_complete:
        offer = new_avg × new_open_complete%
        offer -= (missing_minifig_price × multiplier × count)
    else:
        offer = (weight_kg × incomplete_rate) + (present_minifig_value × 25%)

else if condition == "used":
    if comp_level == "100" AND !accept_used_100 → reject
    if comp_level == "95"  AND !accept_used_95  → reject
    if comp_level == "less" AND !accept_used_mixed → reject

    if comp_level in ("100", "95"):
        offer = used_avg × used_[lvl]_[built|unbuilt]%
        offer -= initial_offer × box_ins_deduction%
        offer -= (missing_minifig_price × multiplier × count)
    else:
        offer = (weight_kg × mixed_rate) + (present_minifig_value × 25%)

offer = round(offer × 2) / 2   // nearest £0.50
if offer <= 0 → reject

Used price fallback logic

// Applied at the top of calculate_offer() before any branch
if (empty($market_prices['used_avg']) || (float)$market_prices['used_avg'] == 0) {
    $fallback_pct = (float) get_option('tee_used_fallback_pct', 70);
    $market_prices['used_avg'] = (float)$market_prices['new_avg'] * ($fallback_pct / 100);
}
private function get_tier_rules($market_value): array
Iterates the tee_pricing_rules option array and returns the first matching tier (min ≤ market_value ≤ max, where max=0 means no upper limit). Falls back to hardcoded defaults if no tier matches.

Class: TEE_Admin_Settings PHP

Defined in includes/admin-settings.php. Registers the admin menu page and all plugin settings via the WordPress Settings API.

Settings group

All settings use the group tee_settings_group. The settings page submits to options.php via settings_fields('tee_settings_group').

Tabs

Tab switching is handled by admin-settings.js — it intercepts nav link clicks, hides all .tee-tab-content divs, and shows the one matching the href. The active tab is persisted in window.location.hash so it survives page reloads.

Frontend JS — Acceptance Helpers JS

A set of small functions that read tee_vars.acceptance (populated from PHP options at page load) and determine what to show in the UI.

// Safe reference to acceptance object with fallback (all enabled)
var _acc = (tee_vars.acceptance)
    ? tee_vars.acceptance
    : { new_sealed: true, new_open: true, used_100: true, used_95: true, used_mixed: true };

// Returns "used" or "new" depending on which condition types are enabled
function getDefaultCondition() { ... }

// Returns "100", "95", or "less" — first enabled completion level
function getDefaultCompletion() { ... }

// Returns true (seals intact) or false (open) based on which new types are enabled
function getDefaultSeals() { ... }

// Shows/hides New and Used condition cards based on whether any subtypes are enabled
function initConditionCards() { ... }
💡
initConditionCards() is called once on page load and does not need to be called again — the acceptance settings are static per page load (they come from PHP). If you need to dynamically update them, you would need to re-localise tee_vars or fetch them via a separate AJAX call.

Frontend JS — Render Flows JS

renderDynamicFlow()

The central rendering function. Called whenever user state changes. Clears the question container and delegates to renderNewFlow() or renderUsedFlow(), then calls updateMinifigsUI() and calculateOffer().

renderNewFlow(container)

Renders questions for the New condition path:

  • Builds filtered sealOpts array from _acc.new_sealed / _acc.new_open
  • If only one option available, auto-selects it (sets userInputs.seals_intact)
  • If seals intact → renders box condition swatches (Like New / Fair / Bad)
  • If seals broken → renders completeness swatches → weight input if incomplete

renderUsedFlow(container)

Renders questions for the Used condition path:

  • Builds filtered compOpts array from _acc.used_100/95/mixed
  • Resets userInputs.completion_level if current value no longer in available options
  • Renders estimated-price notice if setData.prices.used_price_estimated === true
  • Renders completeness swatches → built/unbuilt + box/instructions swatches if not "less"
  • Renders weight input if "less"

renderSwatches(field, options, currentValue)

Pure function — creates a .tee-swatch-group element from an array of {label, value, desc} objects. Marks the matching option as active. Returns the jQuery element without appending it.

bindDynamicEvents()

Called at the end of each render flow. Re-binds .on('click') to all .tee-swatch elements (using .off('click').on('click') to prevent duplicate handlers). Also binds the weight input change event.

WooCommerce Hooks WooCommerce

These hooks are registered as global functions (outside the class) in lego-evaluator.php.

woocommerce_before_calculate_totals action

Function: tee_override_cart_item_price(). Iterates cart items, overrides price with tee_evaluation.price, and sets weight (converted from grams to WC weight unit) on each evaluated item.

woocommerce_get_item_data filter

Function: tee_display_cart_item_evaluation_details(). Adds each evaluation detail key-value pair to the cart item meta display. Skips the image key.

woocommerce_checkout_create_order_line_item action

Function: tee_add_evaluation_to_order_items(). Persists all evaluation details as order item meta. Also saves _tee_image_url (hidden) and _tee_weight_grams (hidden) for admin and shipping use.

woocommerce_order_item_product filter

Function: tee_override_order_item_product_weight(). Called when shipping plugins (e.g. EasyPost) read the product weight from an order item. Reads _tee_weight_grams meta and converts to WC weight unit before calling $product->set_weight().

woocommerce_cart_item_thumbnail filter

Function: tee_override_cart_item_thumbnail(). Replaces the generic product thumbnail with the LEGO set image from BrickLink in the cart page.

woocommerce_admin_order_item_thumbnail filter

Function: tee_override_admin_order_item_thumbnail(). Same as above but for the WooCommerce admin order edit screen. Reads _tee_image_url order item meta.

⚠️
tee_override_cart_item_price uses a guard: if ( did_action('woocommerce_before_calculate_totals') >= 2 ) return; to prevent infinite loops from WooCommerce recalculating totals inside hooks.

Extending: Custom Offer Logic

The cleanest way to add a new set category filter or pricing rule without modifying core files is to extend TEE_Evaluator_Logic.

// my-plugin/my-extension.php

class My_TEE_Evaluator_Logic extends TEE_Evaluator_Logic {

    public function calculate_offer($set_data, $user_inputs) {

        // Example: treat "Technic" sets as a special category
        $name = strtolower($set_data['name'] ?? '');
        if (strpos($name, 'technic') !== false && $user_inputs['condition'] === 'used') {
            // Apply a flat 60% of used average for Technic sets
            $used_avg = (float) $set_data['prices']['used_avg'];
            $offer    = round($used_avg * 0.60 * 2) / 2;
            return $offer > 0 ? $offer : ['rejected' => true, 'rejection_url' => '#'];
        }

        // Fall back to original logic for all other sets
        return parent::calculate_offer($set_data, $user_inputs);
    }
}

// Replace the logic class in the AJAX handler
add_action('wp_ajax_tee_calculate_offer', function() {
    // ... same as original but using My_TEE_Evaluator_Logic instead
    $evaluator   = new My_TEE_Evaluator_Logic();
    $calc_result = $evaluator->calculate_offer($set_data, $user_inputs);
    wp_send_json_success(...);

Extending: New BrickLink API Calls

To add a new BrickLink API endpoint, add a public method to TEE_Bricklink_API (or extend it) that calls the private request() method.

// Example: get a set's known colors
public function get_item_colors($set_number) {
    if (strpos($set_number, '-') === false) {
        $set_number .= '-1';
    }
    return $this->request('GET', "items/SET/{$set_number}/colors");
}

The request() method automatically handles OAuth signing, the BrickLink base URL, debug logging, and error wrapping into WP_Error.

Debugging

Enable Debug Mode

In LEGO Evaluator → General Settings, check Debug Mode. All BrickLink API calls will then be logged to wp-content/plugins/lego-evaluator/tee-api-debug.json. View them in the Logs tab.
